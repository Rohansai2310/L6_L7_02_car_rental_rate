Lab 7: Fuzzing for Input Validation Bugs

Application: Car Rental Rate · Technique: Hypothesis property-based testing

Objective

Use Hypothesis to generate unexpected inputs for the three processor functions, identify crashes, and harden the program so all generated text or None inputs are handled safely.

Figure 1 — Initial fuzz-test failures

$ .venv/bin/python -m pytest test_processor.py -q FFF FAILED test_sanitize_license_plate_no_crash s = None -> AttributeError: 'NoneType' object has no attribute 'strip' FAILED test_parse_trip_mileage_safe s = '' -> ValueError: could not convert string to float: '' s = None -> AttributeError: 'NoneType' object has no attribute 'split' FAILED test_format_rental_invoice_safe s = ':' -> ValueError: invalid literal for int() with base 10: '' s = '' -> IndexError: list index out of range s = None -> AttributeError: 'NoneType' object has no attribute 'split' 3 failed

Hypothesis minimized each failure to a small reproducible input.

Fixes applied

FunctionDefensive behaviour
sanitize_license_plateReturns an empty string for non-text input before stripping delimiters.
parse_trip_mileageReturns an empty list for non-text input; ignores blank, invalid, NaN, and infinite mileage fields while retaining valid finite values.
format_rental_invoiceValidates exactly three record parts, non-empty driver/category, and positive integral days. Invalid records return a clear message.

Figure 3 — Fuzz tests after the fix

$ .venv/bin/python -m pytest test_processor.py -q ... [100%] 3 passed in 0.17s

Conclusion

The completed property tests exercise every processor function against generated Unicode text and None. The processor no longer exposes parsing exceptions for malformed input and preserves expected results for valid records.
